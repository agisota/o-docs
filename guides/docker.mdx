Running the Craft Agents server inside a Docker container is the quickest way to get a self-contained, reproducible deployment on any machine that has Docker installed. The container exposes the WebSocket server on port `9100` and stores all your workspaces, sessions, and credentials in a named volume so your data persists across container restarts, upgrades, and re-deploys.

## Prerequisites

<CardGroup cols={2}>
  <Card title="Docker Engine" icon="docker">
    Docker 20.10 or later installed and running. Check with `docker --version`.
  </Card>
  <Card title="Server image" icon="box">
    The `craft-agents-server` image built from the monorepo or pulled from your container registry.
  </Card>
</CardGroup>

## Quick start with docker run

The command below starts a detached container, binds port `9100`, generates a fresh token, and attaches a persistent volume:

```bash
docker run -d \
  --name craft-agents \
  -p 9100:9100 \
  -e CRAFT_SERVER_TOKEN=$(openssl rand -hex 32) \
  -e CRAFT_RPC_HOST=0.0.0.0 \
  -v craft-data:/root/.craft-agent \
  craft-agents-server
```

<Warning>
  You must set `CRAFT_RPC_HOST=0.0.0.0`. The server's default bind address is `127.0.0.1`, which only accepts connections from inside the container itself. Without this variable set, the published port `9100` will be unreachable from outside the container.
</Warning>

After the container starts, retrieve the token you generated so you can use it to connect:

```bash
# Print the token from the running container's environment
docker exec craft-agents printenv CRAFT_SERVER_TOKEN
```

## Docker Compose

For a more maintainable setup, define the service in a `compose.yaml` file. This makes it easy to version-control your configuration and manage the lifecycle with `docker compose up/down`.

```yaml
services:
  craft-agents:
    image: craft-agents-server
    ports:
      - "9100:9100"
    environment:
      - CRAFT_SERVER_TOKEN=your-secure-token
      - CRAFT_RPC_HOST=0.0.0.0
    volumes:
      - craft-data:/root/.craft-agent
    restart: unless-stopped

volumes:
  craft-data:
```

Start the service:

```bash
docker compose up -d
```

View live logs:

```bash
docker compose logs -f craft-agents
```

<Tip>
  Replace `your-secure-token` in the compose file with a strong random value generated by `openssl rand -hex 32`. Consider loading it from a `.env` file (and adding that file to `.gitignore`) so you never commit the secret to version control.
</Tip>

## Enabling TLS inside Docker

To serve `wss://` from the container, generate or obtain your certificate files and mount them into the container alongside the TLS environment variables:

```bash
docker run -d \
  --name craft-agents \
  -p 9100:9100 \
  -e CRAFT_SERVER_TOKEN=<token> \
  -e CRAFT_RPC_HOST=0.0.0.0 \
  -e CRAFT_RPC_TLS_CERT=/certs/cert.pem \
  -e CRAFT_RPC_TLS_KEY=/certs/key.pem \
  -v ./certs:/certs:ro \
  -v craft-data:/root/.craft-agent \
  craft-agents-server
```

The `:ro` flag mounts the certificate directory as read-only inside the container, which is a good security practice.

## Persistent storage explained

All server data lives in `/root/.craft-agent` inside the container. Mounting a named volume at that path means:

| What's stored | Why it matters |
|---|---|
| Workspaces and sessions | Your conversation history survives container restarts and image upgrades |
| Encrypted credentials | API keys and OAuth tokens don't need to be re-entered after a redeploy |
| Sources and skills | Configured integrations and custom instructions persist automatically |
| Server configuration | Workspace settings, themes, and automations are retained |

If you remove the volume (`docker volume rm craft-data`) all data is permanently deleted, so treat it like any other stateful data store.

## Connecting the desktop app

Once the container is running and you have the token, connect the Craft Agents desktop app in thin-client mode:

```bash
CRAFT_SERVER_URL=ws://<your-server-ip>:9100 \
CRAFT_SERVER_TOKEN=<token> \
bun run electron:start
```

If you enabled TLS, use `wss://` instead of `ws://`. For a self-signed certificate, supply the CA file with the `--tls-ca` flag when using the CLI, or add the certificate to your OS trust store for the desktop app.

<Note>
  Replace `<your-server-ip>` with the actual IP address or hostname of the machine running the Docker container. If you're connecting locally for testing, use `127.0.0.1`.
</Note>
