Automations let Craft Agents react to things that happen in your workspace — a label being added, a session reaching a certain status, a scheduled time — and respond by spawning an AI session, firing a webhook, or both. Once configured, your workflows run continuously in the background without any manual nudging.

## Configuration file

Automations live in a single JSON file per workspace:

```text
~/.craft-agent/workspaces/{workspaceId}/automations.json
```

The file uses a version 2 schema. The top-level `automations` object maps event names to arrays of matchers, each with its own conditions and actions:

```json
{
  "version": 2,
  "automations": {
    "EventName": [
      {
        "name": "Optional display name",
        "matcher": "regex-pattern",
        "actions": [
          { "type": "prompt", "prompt": "Summarise what changed and why it matters" }
        ]
      }
    ]
  }
}
```

You can edit the file directly, or use the CLI for a guided experience:

```bash
craft-agent automation list
craft-agent automation create --event LabelAdd --prompt "Triage the urgent label"
craft-agent automation enable <id>
craft-agent automation lint
```

## Events

<Tabs>
  <Tab title="App Events">
    App events are fired by Craft Agents itself in response to workspace activity.

    | Event | Trigger | Matcher value |
    |---|---|---|
    | `LabelAdd` | A label is added to a session | Label ID (e.g., `bug`) |
    | `LabelRemove` | A label is removed from a session | Label ID |
    | `LabelConfigChange` | Label configuration is edited | Always matches |
    | `FlagChange` | A session is flagged or unflagged | `true` or `false` |
    | `SessionStatusChange` | A session's status changes | New status (e.g., `done`) |
    | `PermissionModeChange` | Permission mode changes | New mode name |
    | `SchedulerTick` | Fires every minute on the clock | Cron expression (see [Cron schedule](#cron-schedule)) |

    <Note>
      Label IDs are case-sensitive and use the lowercase slug, not the display name. A label displayed as "Bug" has the ID `bug`.
    </Note>
  </Tab>
  <Tab title="Agent Events">
    Agent events are fired during a running session — use them to react to tool activity, session lifecycle, or permission requests.

    | Event | Trigger |
    |---|---|
    | `PreToolUse` | Before a tool executes (matcher: tool name) |
    | `PostToolUse` | After a tool executes successfully (matcher: tool name) |
    | `PostToolUseFailure` | After a tool execution fails (matcher: tool name) |
    | `Notification` | Notification received from the agent |
    | `UserPromptSubmit` | User submits a prompt |
    | `SessionStart` | A session starts |
    | `SessionEnd` | A session ends |
    | `Stop` | The agent stops |
    | `SubagentStart` | A subagent is spawned |
    | `SubagentStop` | A subagent completes |
    | `PreCompact` | Before context compaction runs |
    | `PermissionRequest` | Agent requests permission for an operation |
    | `Setup` | Initial workspace setup |
  </Tab>
</Tabs>

## Action types

Each matcher can have one or more actions. Actions execute in order — you can combine a webhook and a prompt in the same automation.

### Prompt action

Spawns a new AI session with the given prompt text. Environment variables (see [Environment variables](#environment-variables)) are expanded inside the `prompt` string.

```json
{
  "type": "prompt",
  "prompt": "The label $CRAFT_LABEL was added to $CRAFT_SESSION_NAME. Triage and summarise the issue.",
  "llmConnection": "my-connection",
  "model": "claude-opus-4-5"
}
```

| Property | Required | Default | Description |
|---|---|---|---|
| `type` | ✅ | — | Must be `"prompt"` |
| `prompt` | ✅ | — | Text sent to the agent. Supports `$VAR` expansion and `@mentions` |
| `llmConnection` | — | Workspace default | Slug of an LLM connection configured in AI Settings |
| `model` | — | Workspace default | Model ID supported by the provider |
| `permissionMode` | — | Workspace default | Permission level for the spawned session (`safe`, `ask`, or `allow-all`) |
| `labels` | — | — | Labels to apply automatically to the spawned session |

### Webhook action

Sends an HTTP request to an external endpoint — useful for Slack notifications, Discord alerts, logging services, or triggering external pipelines.

```json
{
  "type": "webhook",
  "url": "${CRAFT_WH_SLACK_URL}",
  "method": "POST",
  "headers": {
    "Content-Type": "application/json"
  },
  "body": {
    "text": "Session *${CRAFT_SESSION_NAME}* changed status to ${CRAFT_NEW_STATE}"
  }
}
```

| Property | Required | Default | Description |
|---|---|---|---|
| `type` | ✅ | — | Must be `"webhook"` |
| `url` | ✅ | — | Target URL (`http://` or `https://`). Supports `$VAR` expansion |
| `method` | — | `"POST"` | `GET`, `POST`, `PUT`, `PATCH`, or `DELETE` |
| `headers` | — | `{}` | Key-value HTTP headers |
| `bodyFormat` | — | `"json"` | `"json"`, `"form"` (URL-encoded), or `"raw"` |
| `body` | — | — | Request body. Omitted for GET requests |
| `auth` | — | — | Authentication shorthand (`bearer` or `basic`) |
| `captureResponse` | — | `false` | Store response body (up to 4 KB) in automation history |

**Authentication shorthand** — instead of constructing `Authorization` headers manually:

```json
{
  "type": "webhook",
  "url": "https://api.example.com/events",
  "auth": {
    "type": "bearer",
    "token": "${CRAFT_WH_API_TOKEN}"
  },
  "body": { "event": "$CRAFT_EVENT" }
}
```

<Warning>
  Webhook actions only have access to `CRAFT_*` system variables and `CRAFT_WH_*` user-defined secrets. General shell variables like `$HOME` or `$DATABASE_URL` are not available, keeping your system environment isolated.
</Warning>

## Environment variables

Both prompt and webhook actions support `$VAR` and `${VAR}` expansion.

### System variables

Available for all events:

| Variable | Description |
|---|---|
| `$CRAFT_EVENT` | Event name (e.g., `LabelAdd`) |
| `$CRAFT_EVENT_DATA` | Full event payload as JSON |
| `$CRAFT_SESSION_ID` | ID of the session that triggered the event |
| `$CRAFT_SESSION_NAME` | Display name of the triggering session |
| `$CRAFT_WORKSPACE_ID` | Current workspace ID |

### Per-event variables

| Event | Variable | Description |
|---|---|---|
| `LabelAdd` / `LabelRemove` | `$CRAFT_LABEL` | The label that was added or removed |
| `PermissionModeChange` | `$CRAFT_OLD_MODE`, `$CRAFT_NEW_MODE` | Previous and new permission mode |
| `FlagChange` | `$CRAFT_IS_FLAGGED` | `true` or `false` |
| `SessionStatusChange` | `$CRAFT_OLD_STATE`, `$CRAFT_NEW_STATE` | Previous and new status value |
| `SchedulerTick` | `$CRAFT_LOCAL_TIME`, `$CRAFT_LOCAL_DATE` | Current time (`14:30`) and date (`2026-03-09`) |

### Webhook secrets (`CRAFT_WH_*`)

Store sensitive URLs and tokens in your shell profile — never hardcode them in `automations.json`:

```bash
# ~/.zshrc or ~/.bashrc
export CRAFT_WH_SLACK_URL="https://hooks.slack.com/services/T.../B.../xxx"
export CRAFT_WH_DISCORD_URL="https://discord.com/api/webhooks/123/abc"
export CRAFT_WH_API_TOKEN="your-secret-token"
```

Then reference them in your config:

```json
{
  "type": "webhook",
  "url": "${CRAFT_WH_SLACK_URL}",
  "body": { "text": "Hello from Craft Agents!" }
}
```

Restart Craft Agents after adding new variables to your shell profile so they are picked up.

## Cron schedule

For `SchedulerTick` events, use a `cron` field instead of `matcher`. The cron format follows standard Unix convention:

```text
minute  hour  day-of-month  month  day-of-week
```

| Field | Allowed values |
|---|---|
| Minute | `0–59` |
| Hour | `0–23` |
| Day of month | `1–31` |
| Month | `1–12` |
| Day of week | `0–6` (0 = Sunday) |

Common expressions:

| Expression | Meaning |
|---|---|
| `*/15 * * * *` | Every 15 minutes |
| `0 9 * * *` | Daily at 9:00 AM |
| `0 9 * * 1-5` | Weekdays at 9:00 AM |
| `30 14 1 * *` | 1st of each month at 2:30 PM |
| `0 8,17 * * *` | Every day at 8:00 AM and 5:00 PM |

Set `timezone` to an IANA name (e.g., `Europe/Budapest`, `America/New_York`) — defaults to the system timezone if omitted.

<Tip>
  Use [crontab.guru](https://crontab.guru/) to build and verify cron expressions before committing them to your automation.
</Tip>

## Conditions

Conditions are optional filters that run after the matcher or cron matches but before actions fire. If the `conditions` array is absent or empty, actions fire unconditionally.

<Accordion title="Time conditions">
  Gate actions on time-of-day or day-of-week in any timezone:

  ```json
  {
    "condition": "time",
    "after": "09:00",
    "before": "17:00",
    "weekday": ["mon", "tue", "wed", "thu", "fri"],
    "timezone": "Europe/Budapest"
  }
  ```

  | Property | Type | Description |
  |---|---|---|
  | `after` | `"HH:MM"` | Start of time window (inclusive) |
  | `before` | `"HH:MM"` | End of time window (exclusive) |
  | `weekday` | `string[]` | Days: `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun` |
  | `timezone` | string | IANA timezone name |

  If `after` is later than `before` (e.g., `"22:00"` / `"06:00"`), the window wraps past midnight.
</Accordion>

<Accordion title="State conditions">
  Check fields from the event payload — useful for filtering on specific transitions:

  ```json
  {
    "condition": "state",
    "field": "permissionMode",
    "from": "safe",
    "to": "allow-all"
  }
  ```

  | Property | Type | Description |
  |---|---|---|
  | `field` | string | Payload field (e.g., `permissionMode`, `sessionStatus`, `isFlagged`) |
  | `value` | any | Exact match |
  | `from` | any | Previous value (for transition events) |
  | `to` | any | New value (for transition events) |
  | `contains` | string | Array membership check |
  | `not_value` | any | Matches anything except this value |
</Accordion>

<Accordion title="Logical composition">
  Combine conditions with `and`, `or`, and `not` for complex filtering:

  ```json
  {
    "condition": "and",
    "conditions": [
      { "condition": "time", "weekday": ["mon", "tue", "wed", "thu", "fri"] },
      { "condition": "time", "after": "09:00", "before": "17:00" }
    ]
  }
  ```

  | Type | Behaviour |
  |---|---|
  | `and` | All sub-conditions must pass |
  | `or` | At least one sub-condition must pass |
  | `not` | None of the sub-conditions may pass |

  Conditions can be nested up to 8 levels deep.
</Accordion>

## Telegram topic routing

When a Telegram supergroup is paired in **Settings → Messaging → Telegram**, set `telegramTopic` on a matcher to route its spawned sessions into a dedicated forum topic. The topic is created on first use and reused thereafter.

```json
{
  "matcher": "^urgent$",
  "telegramTopic": "Urgent Alerts",
  "actions": [
    { "type": "prompt", "prompt": "An urgent label was added. Triage the session and summarise what needs immediate attention." }
  ]
}
```

| Field | Type | Description |
|---|---|---|
| `telegramTopic` | string (1–128 chars) | Topic name. Created on first use, reused thereafter. Multiple matchers sharing the same value share one topic. |

Topic routing requires a paired Telegram supergroup with Topics enabled, the bot connected and granted the **Manage Topics** admin permission in that group.

## Webhook retry behavior

When a webhook fails, Craft Agents retries it automatically at two levels:

**Immediate retries** — on 5xx errors, timeouts, or connection failures, the request is retried up to 2 times with exponential backoff (1 s → 2 s → 4 s). Client errors (4xx) are not retried — they indicate a configuration problem.

**Deferred retry queue** — if all immediate retries fail, the webhook enters a persistent queue:

| Attempt | Delay | Cumulative |
|---|---|---|
| 1st deferred | 5 minutes | 5 min |
| 2nd deferred | 30 minutes | 35 min |
| 3rd deferred | 1 hour | ~1.5 hours |

Deferred retries survive app restarts. After the final attempt fails, the webhook is marked permanently failed in the automation history, where you can also trigger a manual retry.

## Rate limits

| Event | Max fires per minute |
|---|---|
| `SchedulerTick` | 60 (1 per second) |
| All other events | 10 |

When a limit is hit, further events of that type are silently dropped for the remainder of the 60-second window. This prevents runaway loops where an automation inadvertently triggers itself.

## Complete examples

<Accordion title="Daily morning briefing (cron)">
  Run a briefing session every weekday morning at 9 AM, tagged with `Scheduled` and `morning-briefing` labels:

  ```json
  {
    "version": 2,
    "automations": {
      "SchedulerTick": [
        {
          "name": "Morning Briefing",
          "cron": "0 9 * * *",
          "timezone": "America/New_York",
          "conditions": [
            {
              "condition": "time",
              "weekday": ["mon", "tue", "wed", "thu", "fri"],
              "timezone": "America/New_York"
            }
          ],
          "labels": ["Scheduled", "morning-briefing"],
          "actions": [
            {
              "type": "prompt",
              "prompt": "Good morning! Summarise my open sessions, highlight anything urgent, and list today's priorities."
            }
          ]
        }
      ]
    }
  }
  ```
</Accordion>

<Accordion title="Slack notification when a session is done">
  Send a Slack message whenever any session's status changes to `done`. Requires `CRAFT_WH_SLACK_URL` in your shell profile.

  ```json
  {
    "version": 2,
    "automations": {
      "SessionStatusChange": [
        {
          "name": "Notify Slack on Done",
          "matcher": "^done$",
          "actions": [
            {
              "type": "webhook",
              "url": "${CRAFT_WH_SLACK_URL}",
              "method": "POST",
              "body": {
                "text": ":white_check_mark: Session *${CRAFT_SESSION_NAME}* marked as done"
              }
            }
          ]
        }
      ]
    }
  }
  ```
</Accordion>

<Accordion title="Urgent label → notify + triage session">
  When the `urgent` label is added, fire a Slack alert and immediately spin up a triage session — both actions run in order from a single matcher.

  ```json
  {
    "version": 2,
    "automations": {
      "LabelAdd": [
        {
          "name": "Urgent: Notify and Triage",
          "matcher": "^urgent$",
          "actions": [
            {
              "type": "webhook",
              "url": "${CRAFT_WH_SLACK_URL}",
              "method": "POST",
              "body": {
                "text": ":rotating_light: Urgent label added to *${CRAFT_SESSION_NAME}*"
              }
            },
            {
              "type": "prompt",
              "prompt": "An urgent label was added to this session. Triage it — summarise the problem, identify blockers, and suggest immediate next steps."
            }
          ]
        }
      ]
    }
  }
  ```
</Accordion>

<Accordion title="Permission mode escalation alert">
  Only notify when permission mode changes specifically from `safe` to `allow-all`:

  ```json
  {
    "version": 2,
    "automations": {
      "PermissionModeChange": [
        {
          "conditions": [
            {
              "condition": "state",
              "field": "permissionMode",
              "from": "safe",
              "to": "allow-all"
            }
          ],
          "actions": [
            {
              "type": "webhook",
              "url": "${CRAFT_WH_SLACK_URL}",
              "method": "POST",
              "body": {
                "text": ":warning: Permission escalated from safe to allow-all in *${CRAFT_SESSION_NAME}*"
              }
            }
          ]
        }
      ]
    }
  }
  ```
</Accordion>
