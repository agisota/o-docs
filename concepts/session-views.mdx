The session collection supports three views of the same underlying sessions: **List**, **Board**, and **Table**. All three share the same filters, grouping, and ordering. Switching views never loses context; it only changes how sessions are drawn.

Use the view toggle at the top of the session collection to switch between them:

- **List**: chat-oriented rows for day-to-day triage and quick reading.
- **Board**: kanban columns for stage-based work (see the board's own column settings).
- **Table**: dense, spreadsheet-style rows for scanning and bulk editing many sessions at once.

## Filter chips

Filter chips sit above the collection and narrow what's visible across every view. Chips combine with **AND** across dimensions and **OR** within a dimension. For example, `status = In Progress` **AND** (`priority = Urgent` **OR** `priority = High`).

You can filter by:

- **Status**: any workspace status, including custom ones.
- **Priority**: Urgent, High, Medium, Low, or None.
- **Project**: one or more workspace projects.
- **Labels**: any labels attached to the session.
- **Due date**: Overdue, Today, or No due date.
- **Flag**: only flagged sessions.
- **Unread**: sessions with unread activity.
- **Model**: the LLM model used.

Craft stores filters per workspace so they persist between app launches. Click **Clear filters** to remove all chips at once.

<Note>
  Sidebar smart views still apply on top of chip filters. Visible sessions must satisfy both the smart view and the chips.
</Note>

## Display popover

The **Display** popover controls grouping, ordering, and which properties appear on each row. Open it from the collection toolbar. Settings persist per workspace.

### Group by

Group sessions into sections with counted headers.

| Group by | What it groups on |
|---|---|
| **None** | A single flat list |
| **Status** | Todo, In Progress, Needs Review, Done, and any custom statuses |
| **Priority** | Urgent → High → Medium → Low → None |
| **Project** | Workspace projects |
| **Due date** | Overdue · Today · This week · Later · No date |
| **Label** | Session appears under its first label (alphabetical) |

Toggle **Show empty groups** to hide sections with no matching sessions.

### Order by

Choose how sessions sort inside each group.

- **Manual**: drag to reorder. See [Manual rank](#manual-rank).
- **Priority**: Urgent first.
- **Due date**: earliest first when ascending.
- **Updated**: most recent message activity.
- **Created**: when the session was created.
- **Name**: alphabetical by title.

Switch between **Ascending** and **Descending** to reverse the direction.

### Properties

Toggle which columns and inline fields appear: Status, Priority, Project, Labels, Due date, Model, Updated, Created, and Flag. Hidden properties still filter and sort. They only stop rendering on the row.

### Show completed

Off by default. When off, sessions with a terminal status (`Done`, `Cancelled`) are hidden across all views unless you add an explicit **Status = Done** chip, which always wins.

<Tip>
  On the board, columns still come from your board settings. The Display popover's `Group by` doesn't override columns — the ordering you pick applies inside each column.
</Tip>

## Session fields

Every session has the following fields. You can edit them inline on the table, on list rows (where the property is visible), and in the bulk bar.

### Priority

Priority is one of `Urgent`, `High`, `Medium`, `Low`, or `None` (default). Click the priority cell on any row to change it without opening the session.

### Due date

An optional calendar date. Craft stores picked dates as UTC noon of the chosen day and displays them in your local timezone. A session becomes **Overdue** when its due date is earlier than today and its status is not terminal (`Done`, `Cancelled`). Craft visually highlights overdue rows.

### Manual rank

Every session has a manual rank that Craft uses when **Order by** is set to **Manual**. Craft backfills ranks the first time you load a workspace, ordered by most recent message activity. An ascending manual sort matches your familiar ordering until you drag something.

To reorder:

1. Set **Order by** to **Manual**.
2. Hover a row and use the drag handle to move it between two siblings.

Cross-group drags update the writable field for that group and re-rank in the destination. For example, dragging into a different **Priority** group sets the priority. Cross-group drags are disabled when grouping by **Label**.

## Table view

Table mode renders a virtualized, dense row per session so you can scan and edit many at once. Rows stay interactive on workspaces with thousands of sessions.

- Click the title or row body to open the session.
- Click a status, priority, or flag cell to edit inline without opening.
- Group headers show counts and can be collapsed. Collapse state persists between sessions.
- An empty state appears when no sessions match the current chips, with a shortcut to clear filters.

## Bulk actions

Table and list rows have selection checkboxes. Select rows individually, or click the header checkbox to select every currently visible row (collapsed groups are excluded). `Shift`-click a second row to select a contiguous range.

When one or more sessions are selected, the **Bulk actions** bar appears with:

- Set status
- Set priority
- Set project
- Add or remove labels
- Set due date
- Flag / Unflag
- Archive
- Clear selection

Archiving a group of sessions asks for confirmation when you select more than one session, or when any selected session is still processing. Craft skips processing sessions and reports them as failed with reason `busy`. The rest complete.

<Note>
  Bulk actions apply to at most 200 sessions per request. Selecting more than 200 rejects the request with a `BULK_LIMIT` error. You cannot change rank in bulk. Reorder manually with drag instead.
</Note>

Selection clears automatically when you switch views, change filter chips, or press `Escape`.

## Example: triage this week's urgent work

A common triage flow using the shared collection tools:

1. Add chips: `Status = Todo` **OR** `In Progress`, `Priority = Urgent` **OR** `High`.
2. Open **Display**, set **Group by = Due date**, **Order by = Due date**, direction **Ascending**.
3. Switch to **Table** to scan due dates across sessions.
4. Select a range of overdue rows and use **Bulk actions → Set priority → Urgent** to escalate.
5. Switch to **Board**. The same sessions appear, now bucketed by kanban column with the priority order you chose inside each column.
